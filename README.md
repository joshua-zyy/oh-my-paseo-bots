# oh-my-paseo-bots

给 [Paseo](https://github.com/getpaseo/paseo) 装一支有长期身份和记忆的固定 Bot 团队：你交办事情，主 Bot 负责澄清、分工、跟进和交付，其他 Bot 用自己的专长和记忆配合。

所有执行都跑在 Paseo 上——模型与 Provider 配置、会话、工作区、权限、多 Agent 通信和定时调度全部复用宿主。插件只补充 Paseo 本身没有的四件事：Bot 身份、长期记忆、事项关联、受控办公外发。

## 它解决什么问题

- **不用每次重建上下文**：Bot 有固定身份和确认过的长期记忆，新对话还能接着聊同一件事。
- **不用自己管理执行 Agent**：交办后由 Chief 拆分、委派、跟进、核对产物并汇总，执行过程不会混进你的普通工作区列表。
- **轮次结束不等于事情结束**：事项有明确状态、跟进和交付证据，没有完成报告不会被当成完成。
- **外发有闸门**：邮件先给草案，确认或预先授权的固定动作才执行，结果不确定时如实保留未知。

## 主要能力

| 能力 | 说明 |
| --- | --- |
| 同事页 | 侧栏「同事」进入；每位 Bot 一个持续聊天，事项完成或取消不会关掉对话 |
| 长期记忆 | 明确记忆与推断候选分开；精确重复不新增，可查看来源和变更、纠正、遗忘／拒绝及恢复归档；候选和归档条目不注入上下文；记忆读取工具区分创建来源与当前正文操作出处，未知出处不撤销确认 |
| 团队共享记忆 | 可在记忆页预览发布，或在对话中明确要求发布当前场景的已确认条目；只分享所选正文副本，不复制私聊来源或历史，原条与副本分别管理 |
| Chief 配置引导 | 向 Chief 描述需要的同事和能力；它发现已有能力并完成普通技能配置，复用接收方已批准的相同 MCP 不再二次确认；新增或改变 MCP 范围才进入「能力待确认」。仅后续新对话／任务使用，不自动安装或登录 |
| 能力方案记录 | 在真实来源对话显示待确认、已保存或已拒绝状态卡；查看回原能力入口，不批准。有效状态行驱动待办刷新；来源不可用或记录发布失败会保留待核对，不作为其他后台业务的实时通知替代 |
| Chief 委派 | 主 Bot 澄清目标、分派给固定同事、跟踪进度、核对实际产物后汇报 |
| 项目频道 | 设置成员、管理员、目录与共同说明；普通消息由管理员回应，支持@一位或多位成员并合并本群原生历史；群记忆仅留本群，支持来源查看及归档恢复；管理员可交办成员并核对原生回报 |
| 事项与跟进 | 支持开始、跟进、完成（须附摘要与证据）、定向取消；可中断当前回复 |
| 集中待办 | 侧栏与同事页共享各 Bot 的待决定、异常和结果未知；当前客户端操作会刷新，后台／其他客户端变更可能需手动刷新。查看只回原入口，不自动批准、发送、重派或完成，读取失败明确提示 |
| 重要提示 | 明确的重要业务项通过宿主应用内提示，按原因与轮次去重，不额外提示普通在途、成功或原生请求；已用合成样本验证桌面实际显示、跨合成页面与窄窗口。后台变更可能需手动刷新，OS／手机触达尚未验证 |
| 独立例程 | 按 Cron／时区创建周期任务，关闭客户端后仍可执行（需 daemon 在线） |
| 每 Bot 配置 | 模型、工作目录、模式、思考等级、技能索引、MCP 连接各自独立 |
| 受控办公 | Gmail 读取、草稿、单次或预授权发送与回查；飞书文档只读 |
| Gmail新邮件检查 | 在既有例程内明确启用，沿用其频率与本同事批准的账户／查询；新增邮件派发独立事项，重复与未知结果复用原创建。已用模拟邮件验证真实原生例程到事项交付及重复事件复用；既有 Gmail 读取已真实验证，本新增事件链尚未用真实新邮件验收 |
| 可编辑 Excel | 固定内置技能可由用户在「技能」中选择或由 Chief 配置；制作／另存修改原生 XLSX、真实 Excel 重算及独立回读，PDF 仅作检查副本，不替代工作簿 |
| 可观测 | 工作日志、原生历史分页、按需读取会话用量；归档的同事可恢复 |

## 环境要求

- Paseo `0.15.3`（当前已验证基线；正式发版前只维护最新版本，不保留旧版兼容）
- Node.js 22 与 npm（本地构建）
- 邮件／飞书能力需自备并登录连接器：`gws 0.22.5`（Google Workspace）、`lark-mcp 0.5.1`（飞书）。插件不创建 OAuth 服务，也不代管凭据
- 选定 Excel 流程需已有 Python/openpyxl；真实重算与检查 PDF 当前适配 Windows 已安装且可用的 Microsoft Excel，经已有授权的 Paseo 原生工作区终端执行。插件不自动安装 Office、不扩大命令或数据授权；条件不足时如实报告未重算。

Word、PDF、PPT 等文档操作优先复用 Agent 已有工具与技能，不另建专属 Office 执行层。可用性取决于 daemon 机器的依赖、账户与授权；条件不足时反馈实际缺口，不自动安装办公软件、代登录或扩大权限。当前 Word/PPT 尚未完成与上述 Excel 同等的真实流程验证。

网页工作同样复用 Agent 已有工具。需要独立 headless 运行时，使用 daemon 机器上可用且已授权的 Playwright 等工具；Paseo 内置 `browser_*` 仍依赖桌面客户端。已实测本地合成网页的读取、填表、回执核对与截图／trace，尚未验证完整客户端退出后的运行。

## 安装

```bash
npm ci
npm run build
paseo plugin install /absolute/path/to/oh-my-paseo-bots
paseo plugin ls
```

源码更新后重载插件，不要为此重启 daemon：

```bash
paseo plugin reload oh-my-paseo-bots
paseo plugin logs oh-my-paseo-bots
```

## 开始使用

1. 打开侧栏「同事」，默认进入主 Bot（Chief）的持续聊天。
2. 直接说明要办的事：目标、交付物、可用范围和完成条件越具体，Bot 越少来回确认。
3. 需要新同事时点「添加同事」填名称与职责；Chief 也能在授权内自行登记固定同事。
4. 同事菜单里可以改：模型、工作目录、思考等级、技能、MCP 连接、办公范围。
5. 「例程」页创建周期任务；「工作记录」看事项和交付证据；「记忆」页查看来源、纠正或遗忘，也可拒绝候选、恢复归档。
6. 需要新话题时点「新对话」，旧对话和未结事项都保留。

Gmail 增量检查默认关闭。先配置同事的既有 Gmail 账户和读取查询，在「例程」展开目标例程、填写新邮件到达后的交付要求后确认启用。每次检查会运行模型，并非实时推送；启用时以当前游标为基线，不补跑旧邮件。账户、查询或工作要求变化需另建例程，游标失效时先核对缺口；停用检查不取消其他例程工作或已派发事项。

在聊天消息框切换模型或工作区，只影响当前对话的后续消息，不修改同事默认配置。新执行会话首次发送时交接预算内的历史原文，未包含的内容仍可按需查读；已运行事项不迁移或重新派发。短合成对话的跨后端承接已实测 Claude ↔ Codex，也已用合成事项验证切换后查回交付报告及输入缺失的阻塞回报；其他后端尚未完成同等验收。

## 安全与边界

- 当前先交付并验收桌面 Paseo 功能；手机端兼容与通知触达待功能稳定后再处理，暂不宣称移动端已完成适配。
- 插件在 Paseo 中属可信代码，**没有沙箱**；Bot 的工具绑定、独立目录都只是工程约束，不是安全隔离。
- Claude Bot 每次原生打开／恢复时设置自动记忆关闭变量，保留认证及个人／项目 CLAUDE.md；已有运行进程下次重开才生效。沿用已登记 Bot 标签的纳管入口，不涵盖未纳管的独立原生专家，也不阻止普通文件工具访问或擦除原生历史。
- 外发、破坏性操作、付款和新增授权始终需要你确认；创建例程本身不带来这些权限。
- 超时不等于没执行。结果无法核实时会保留「不确定」并请你判断，不会盲目重发。
- 后台跟进与例程依赖 daemon 与所需连接在线；Windows 桌面默认退出可能停掉托管的 daemon。
- 未验证：完整客户端退出后的网页工作、任意真实网站／登录流程、Google Workspace 与飞书的完整接口、平台计费告警。
