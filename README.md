# paseo-guys

面向单用户自托管的固定 Bot 团队插件，执行、会话、委派和权限复用 Paseo。

当前代码目标为已发布的 **Paseo 0.12.x**（开发机器 app、bundled CLI 和 daemon 均核实为 0.12.0）。已实现固定身份、记忆、办公动作和事项跟进的插件接线；首版实际验收尚未完成，已验证与未验证范围如下。

已在 0.12.0 宿主完成合成资料的原生委派、专家产物核对、记忆纠正后新会话读取、heartbeat 触发与停止、并发创建幂等和显式取消验证。原生浏览器已在桌面 Host 在线、用户临时授权开启工具的条件下完成 `example.com` 单页导航、读取及快照核对，测试后已恢复关闭。办公连接器的指定范围实际读取已通过下述适配器检查；客户端关闭、daemon 重启与插件界面仍未验收，无桌面时的后台浏览器能力未验证。

1. `npm ci` 安装开发依赖。
2. `npm run typecheck` 检查已发布 SDK 契约；`npm test` 编译并运行本地单元与离线契约测试。
3. `index.client.tsx` 提供固定同事入口，创建 Bot、开始或找回原生会话、查看和纠正记忆。工作目录与 provider/model 使用宿主已有配置，插件不登录模型、不自动更改工具授权。

Bot 工具通过标准 MCP SDK 接入插件进程内的回环 HTTP 端点，共享同一存储。推断只提交候选，用户在入口确认；明确记忆工具回查原生用户消息及原文内容后保存。记忆工具和日志支持分页读取旧记录；日志区展示原生轮次观察与损坏行提示，轮次结束不等于任务完成。

入口显示工具连接状态。端点保持原端口和凭证供会话恢复；端口冲突或状态文件损坏会明确报错，原生会话仍可打开。此时应排查占用或从备份恢复 `mcp/endpoint.json`；删除并重建该文件会更换端口和凭证，已有会话的工具配置将失效，需要新建会话。插件不会自动重建端点。

办公区按 Bot 配置固定 Gmail 账户、现有 `gws` 登录目录与允许查询，以及飞书应用和文档白名单。当前适配基线为 `gws 0.22.5` 与 `lark-mcp 0.5.1`，需要使用者另行安装并登录；插件不自动安装连接器或创建 OAuth 服务。飞书只读取 docx 纯文本与指定 wiki 节点，不开放默认工具集中的写接口。飞书连接器的 token 续期由其自身处理，keyring 不可用时重启可能需要重新登录，尚需目标环境验证。

已在无账户的独立验收目录核对这两个固定版本的启动、Google Discovery 方法声明、媒体上传 dry-run 和飞书两项只读工具目录。另经用户指定范围授权，使用项目的 GmailClient 读取 3 封 GitHub 通知，使用 FeishuReader 经官方连接器读取一份白名单 docx 正文；飞书新进程可恢复有效登录。上述实测未经过宿主 Bot/MCP 办公调用链，不代表该完整链路、真实账户越界拒绝、wiki 节点读取、OAuth 续期、草稿创建或发送已通过。

邮件先登记待确认的完整内容，用户可单次确认，也可给当前事项批准账户、查询、收件人、正文和来源完全相同的固定动作并撤销。发送前重新核对实际账户、来源范围和云端草稿；仅创建草稿不表示发送成功。写后超时或回执丢失保留“结果不确定”，回查确认前不会重发，也不阻塞其他独立事项。Gmail MIME 使用 Nodemailer 本地生成及 MailParser 核对，经 gws 的媒体上传发送，不使用 SMTP；临时 `.eml` 位于 gws 配置目录，正常与失败路径都会尝试删除，进程强杀可能留下文件，访问控制由该目录权限决定。

每个原生根会话关联一个事项，入口展示专家标识、交付摘要、证据和跟进登记。主 Bot 通过原生委派取得专家结果，仅记录父子标识，不给专家复制根 Bot 的记忆工具或历史。跟进使用本事项 Agent 的原生 heartbeat；需在宿主设置填写已有 Paseo CLI 路径及当前 daemon 的绝对 home。原生名和 target 与事项绑定。CLI 创建不是同名幂等操作，回执未知或进程中断留下待确认记录时保留未知并提示人工核对，不自动重建；创建回执不代表已经执行。

入口的“取消事项”及 Bot 的显式完成工具会先保存停止状态，再归档对应原生会话与专家、清理已知跟进。完成必须附带交付证据，轮次结束不会自动完成事项。取消工具核对最新完整用户原话的来源，自然语言意图仍由主 Bot 判断。归档可能中断 Bot 当前回复，因此摘要与证据在入口持久可见，不能仅凭工具回执宣称用户已收到最终回复。停止后拒绝新的插件办公推进和跟进，已准入的外发可能完成，未知结果仍可回查。Paseo 的单轮停止按钮只取消当前轮次；手工再次发送原生消息可能恢复会话，但不会清除插件中的事项停止状态。

业务元数据默认保存在 daemon 机器的 `~/.paseo-guys`，可由进程环境变量 `PASEO_GUYS_DATA_DIR` 指定目录。每个 Bot 保存身份、原生会话标识和记忆，不复制原生聊天历史。仅支持单 daemon、单插件实例写入同一目录；可信插件与工作目录不构成安全隔离。修改记忆不会擦除原生历史和备份。

插件安装、启用、真实模型、办公账户与 E2E 验收需要另行授权。`npm test` 不执行这些操作。`npm run build` 执行类型编译及客户端／服务端 esbuild bundle 检查，不等同于宿主编译或插件加载通过。
